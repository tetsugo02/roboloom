# leader の重力補償の調整

leader の腕を，手を離してもその場に留まり，ある程度の力で押したときだけ動くようにします．
ここでは，補償の電流の決まり方，`gain` と `hold_mA` の意味，それに `roboloom tune-gravity` で関節ごとに手で調整する手順を説明します．

## 1．送る電流の式

制御の周期ごと（leader の `poll_hz`，既定 60 Hz）に，関節ごとの電流を次の式で決めます．

```
送る電流 = 上限で切る( ランプ × ( gain × g(q) + 保持 − kd × 速度 ) + 可動域の押し戻し )   [mA]
```

| 項 | 意味 | どこで決まるか |
| --- | --- | --- |
| g(q) | 姿勢 q で関節を保つのに要る電流を，重力モデルが予測した値 | `identify-gravity` で同定（`calibration/gravity_<side>.yaml`） |
| gain | g(q) に掛ける倍率 | `tune-gravity`（`calibration/gravity_tuning_<side>.yaml`） |
| 保持 | 置いた位置に引き留める電流．最大 ±`hold_mA` | 同上 |
| kd | 速度に比例するブレーキ（今は 0） | `nodes/leader_gravity.yaml` |
| ランプ | 起動直後の `ramp_s` 秒で，0 から 1 に上がる | 同上 |
| 押し戻し | 可動域の外に出たときだけ，外に出た量に比例してかかる | `calibration/travel_<side>.yaml` と `barrier_mA_per_count` |
| 上限 | `max_current_mA`．EEPROM の Current Limit でもモーター側で同じ値に切られる | `nodes/leader_gravity.yaml` |

モーターの力（トルク）は，電流にほぼ比例します．XC330 の電流の単位は 1 mA です．

## 2．gain：重さをどれだけ消すか

g(q) はあくまで予測です．効き方を決めるのは「送った電流 ÷ 実際に必要な電流」の比で，補償の割合はおおよそ次のとおりです．

```
補償の割合 ≈ gain × g(q) ÷ 実際に必要な電流
```

予測が正しければ，gain 1.0 で補償の割合は 100% になります．
研究室の機体では，位置制御で測った保持電流が，ギアの静止摩擦のために実際より小さく出ました．そのため，g(q) は必要な電流の約半分になりました．

| 例：右肩 sh_roll，腕を横に水平 | 値 |
| --- | --- |
| g(q) | 約 58 mA |
| gain 1.0（58 mA を送る） | 手を離すと，補償なしと同じように落ちた |
| gain 2.0（114 mA を送る） | 留まった（わずかに上がった） |
| 実際に必要な電流（推定） | 約 100 mA．gain 1.8 で約 100% |

| 補償の割合 | 手を離したときの関節 |
| --- | --- |
| 0% | 補償なし．トルクを切ったときと同じように落ちる |
| 50% 程度 | 重さは半分になるが，落ちる |
| 約 100% | 重さが消える．ギアの摩擦で，その場に留まる |
| 100% を大きく超える | ゆっくり上がっていく |
| マイナス（向きが逆） | 落ちるのを速める |

摩擦があるので，100% ちょうどでなくても留まる幅があります．

## 3．hold_mA：どれくらいの力で押したら動き出すか

「押し負けたら動く保持」です．摩擦をソフトで足すものと考えてください．

- 関節を，今いる位置にばね（`hold_kp` mA/カウント，既定 1.0）で引き留めます．引き留める力は `hold_mA` を超えません．
- それより強く押すと，引き留める位置が手の動きについていきます．手を離すと，そこで止まります．
- 重力モデルの誤差が `hold_mA` 以内なら，どの姿勢でも関節は留まります．
- 代わりに，動かし始めるときに，`hold_mA` 分だけ余計に力が要ります．
- 例：`hold_mA: 30`，`hold_kp: 1.0` なら，30 カウント（約 2.6°）押し込むまでは戻ろうとし，それを超えると滑ります．

gain は「重さをどれだけ消すか」，`hold_mA` は「どれくらいの力で押したら動き出すか」を決めます．この 2 つは別々に調整します．

## 4．感触ごとの調整

| 感触 | 原因 | 調整（`tune-gravity` のキー） |
| --- | --- | --- |
| 置いても，ゆっくり下がる | 補償が足りない（誤差が保持を超えている） | gain を上げる（`]`，+0.1） |
| 置くと，ゆっくり上がる | 補償しすぎ | gain を下げる（`[`，−0.1） |
| 動かし始めが重い，引っかかる | 保持が強すぎる | `hold_mA` を下げる（`-`，−5 mA） |
| 姿勢によって下がったり上がったりする | 姿勢ごとの予測の誤差 | `hold_mA` を上げる（`=`，+5 mA）．根本的には，電流制御で測り直す |

## 5．`tune-gravity` の手順

前提：
- `identify-gravity`，`measure-travel`，`commission` が済んでいること（`.roboloom/<robot>/README.md` の手順 3〜6）．
- dataflow を止めておくこと．

```bash
uv run roboloom tune-gravity rakuda2/experiment_gravity leader right_arm --hardware
```

1. 腕を支えたまま起動します．電流は `ramp_s` 秒かけて上がります．調整中は，ほかのグループ（反対の腕）は脱力しています．
2. 画面の上に，式と各値の意味，感触ごとの調整表が出ます．中央の表には，関節ごとの次の値が出ます．
   - ID，gain，hold，g(q)，送った電流，実際の電流，位置，速度
   - 状態：`gravity`（重力補償だけ），`holding`（保持が効いている），`sliding`（押し負けて滑っている），`free`（何もしない），`off`（比較のため重力補償を切っている）
3. 「guide」の欄に，選んだ関節で重力がかかる姿勢が出ます．その姿勢に置いて手を離し，その関節がどう動くかを見ます．
4. 4 節の表に従って，キーで gain と hold を変えます．値はすぐに反映されます．
5. `0` を押すと，その関節の重力補償だけを切って，補償なしの感触と比べられます．もう一度押すと戻ります．
6. ↓（または `j`）で次の関節に移ります．`gain 0` で重力の影響が小さい関節（ねじりの関節など）は，そのままにして次へ進みます．
7. `s` で保存します（`calibration/gravity_tuning_right.yaml`）．`q` で終了します．未保存なら確認が出ます．
8. 左腕も `left_arm` で同じように調整します．

調整した値は，`roboloom run rakuda2/experiment_gravity --hardware` でそのまま使われます．

## 6．安全のための仕組み

- **EEPROM の Current Limit：** PC が止まっても効く，唯一の守りです．
  - XC330 では，Bus Watchdog が作動しても電流は止まらず，そのときの電流で固まります（2026-10-23 に試験）．
  - そのため，上限は必要な分のすぐ上に設定します．例：肩 150 mA，肘 100 mA，手首 60 mA．
  - gain を上げて上限に張り付く場合は，`max_current_mA` と EEPROM の両方を見直し，もう一度 `commission` を実行します．
- **暴走検知：**
  - 次の場合は，腕が脱力し，画面に `STOPPED` と出ます．
    - 可動域＋`range_margin` の外に出た．
    - 電流をかけている関節が `max_velocity` を超えて動いた．
  - 腕を支えてから `r` で再開します．
- **Watchdog：** 制御が `bus_watchdog_ms`（500 ms）以上止まると Watchdog が作動します．毎周期これを確かめ，作動していたら腕を脱力させます．100 ms では，たまに起きる 130 ms 程度の遅れで作動してしまいました．

## 7．同定の限界と，根本的な直し方

- g(q) の大きさが半分程度に出たのは，位置制御で保持電流を測ったためです．
  - 静止摩擦があると，腕は摩擦の幅の中のどこでも止まれます．
  - そのため，上から近づけた場合と下から近づけた場合の 2 回の平均が，重力を表しません．
- 電流制御で測れば，この影響を受けません．電流を少しずつ上げて動き出す値と，下げて落ち始める値を求め，その中間をとります．
- 測り直すまでは，gain で量を補正し，hold で姿勢ごとの誤差を吸収します．
- 体感を数値で確かめたいときは，`gravity-check` が使えます．同じ姿勢で，gain の倍率を変えて手を離し，各関節が動いた量を比べます．

```bash
uv run roboloom gravity-check rakuda2/experiment_gravity leader right_arm --poses 1 --scales 1,0,2,-2 --hardware
```
