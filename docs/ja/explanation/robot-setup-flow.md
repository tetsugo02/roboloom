# 機体を立ち上げる段階

実機を初めて動かすまでの作業を，どのロボットでも同じ6つの段階に分けます．ロボットごとのtutorial（[Rakuda2](../tutorials/rakuda2/index.md)，[PiPER＋Pika](../tutorials/piper-pika/index.md)）は，この順に並んでいます．

```mermaid
flowchart LR
  A["1. 設定を作る<br/>init"] --> B["2. 機器を特定する<br/>setup / probe"]
  B --> C["3. 読み取りで確かめる<br/>validate / probe"]
  C --> D["4. 保持を確かめる<br/>check-hold"]
  D --> E["5. ゆるい設定で動かす<br/>run"]
  E --> F["6. 絞る<br/>測って書き足す"]
```

| 段階 | すること | 動かすか |
| --- | --- | --- |
| 1. 設定を作る | `roboloom init <robot>` でテンプレートを写す．機体ごとに測る値は `SET_` で残っている | 動かさない |
| 2. 機器を特定する | どのポート・CANインターフェース・トラッカーがどの機器かを調べて書く | 動かさない（読むだけ） |
| 3. 読み取りで確かめる | `validate` で設定を，`probe` で関節角・温度・異常を確かめる | 動かさない |
| 4. 保持を確かめる | `check-hold` で，指令が止まったときに腕が保持するかを測る | 有効化する |
| 5. ゆるい設定で動かす | 遅い速度で，作業範囲などは決めずに，まず遠隔操作が通ることを確かめる | 動かす |
| 6. 絞る | 道具の寸法，作業範囲，関節の範囲を測って書き足し，速度を上げる | 動かす |

## なぜこの順か

- **動かす前に，読むだけで分かることを済ませる．** 段階1〜3は機器を有効にしません．ポートの取り違えや配線の問題は，ここで見つけます．
- **機器の特定は設定から切り離す．** USBの差し口やCANの名前は，PCや配線を変えると変わります．`roboloom setup` は，機器を手で動かして（腕なら関節を回す，Senseなら開閉する）変化したものを特定し，設定に書きます．機器を替えたときは，同じコマンドで確かめ直せます．
- **最初の遠隔操作はゆるい設定で行う．** 作業範囲や道具の寸法は，遠隔操作できるようになってからの方が測りやすい値です．初回は省略でき，関節の範囲とIKだけが目標を制限します．そのぶん速度を落とし，周りを空けて行います．
- **絞るのは最後．** 動くことを確かめてから，安全のための制限を実機に合わせて狭めます．

## 管理者に頼むこと

rootが要る作業は，段階2の前に管理者に頼みます．roboloomはsudoを呼びません．

- シリアルポートを開く権限（`dialout` グループ）
- 機器ごとのudevルール（例：Viveトラッカーの `81-vive.rules`）
- CANインターフェースを1 Mbpsで有効にする（`roboloom setup` が実行するコマンドを表示します）
