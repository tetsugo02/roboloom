# Lessons

## 2026-10-23：制御モードを機体の今の使い方で決めつけない

- 状況：Rakuda の follower は位置制御で使われているため，重力補償は leader だけと考え，follower の制御モードを固定する前提で質問した．
- 修正：将来はバイラテラル制御を行い，follower も電流制限つき位置制御や電流制御で動かしうる．モードは柔軟に切り替えられる設計にする．
- ルール：
  - 機体の現在の運用（位置制御，トルクオフの leader など）を，設計上の制約として扱わない．
  - 制御モードは，差し替え可能な制御則として leader と follower に共通で設計する．
  - 「今回，実機で有効にする範囲」と「設計が許す範囲」は分けて確認する．

## 2026-11-02：設定ファイルの名前に用途と違う語を使わない

- 状況：機能の組み合わせごとに `experiment_*.yaml` を作っていたのを，オプション付きの1ファイルにまとめる計画で，`experiment` という名前は残すつもりでいた．
- 修正：利用者から「`experiment` で始まる名前は誤解を招く」と指摘され，`.roboloom/<robot>/config.yaml` に改めた．
- ルール：
  - ファイル名やコマンドの引数名は，その中身が何かで付ける（ロボットの設定なら config）．実験の一回分のように読める語を，常設の設定に使わない．
  - 構成を作り替えるときは，既存の命名も見直す対象に含めて計画に書く．

## 2026-11-03：一括置換はリポジトリの管理下のファイルだけに当てる

- 状況：名前を一括で置き換える自作スクリプトを，引数にリポジトリの根（`.`）を渡して走らせた．`.venv`（lerobot など）と `.claude/worktrees/` の古い worktree まで書き換えた．uv は `.venv` のファイルを uv のキャッシュにハードリンクしているので，同じ inode を共有する別のプロジェクトの `.venv` にも及んだ．`uv pip install --reinstall` もキャッシュから同じ壊れたファイルをリンクし直すだけで，直らなかった．
- 直し方：dist-info の RECORD のハッシュで壊れたファイルを見つけ，キャッシュを使わずに取り直した wheel の中身を同じ inode に書き戻した．
- ルール：
  - 一括置換の対象は `git ls-files`（必要なら `git ls-files --others --exclude-standard`）で列挙する．ディレクトリを再帰でたどらない．
  - `.venv`，`.claude/`，`site/`，`datasets/`，`logs/` を対象に含めない．
  - 置換のあとは `git status` で変わったファイルが想定どおりか確かめる．

## 2026-11-03：置換の検索文字列が空でないことを確かめる

- 状況：7031e88 で docs の語を置き換えたとき，検索文字列が空のまま `str.replace("", 新しい文字列)` が走り，`docs/ja/contribution/bilateral.md` の全文字の間に「| estimator | `follower`，」が入った（31 KB → 510 KB）．Markdown としては壊れないので，strict の docs ビルドもテストも通り，次の段階の作業で別の用事で開くまで気づかなかった．
- 直し方：壊れる前の版（bc0cd5a）から戻し，本来の置き換え（robot → follower）を英語版と見比べて当て直した．
- ルール：
  - 置換の表を使うときは，検索文字列が空でないことと，各文字列がちょうど想定の回数だけ現れることを `assert` してから置き換える．
  - コミットの前に `git diff --stat` を見て，行数やファイルの大きさが想定より大きく変わったファイルがないか確かめる．
